# Roves Blitz + Deno/V8 probe

Isolated Windows feasibility probe; it is not production code and is not connected to the main Cargo workspace.

## Runtime ownership

Deno `deno_core` and its V8 isolate are the only JavaScript runtime. Guest JavaScript runs through that runtime. No privileged `Deno.*` APIs are exposed. Blitz supplies HTML parsing, DOM, CSS/style resolution, layout, painting and the candidate native shell. The high-level `blitz` launcher is intentionally avoided because Roves needs to own its event loop and embedder policies.

The selected crates are the official DioxusLabs line, moved on 2026-11-07 from the stable 0.2 releases to `0.3.0-beta.4` (`blitz-dom`, `blitz-html`, `blitz-shell`, `blitz-paint`, `blitz-traits`) with `stylo 0.22.0`, `anyrender 0.14.0`, `anyrender_vello_cpu 0.18.0` and `deno_core 0.413.0`, all pinned exactly. The 0.2 line had three defects that 0.3.0-beta.4 already fixes (below). The port was checked by CI only (no local build, by request). `cargo tree -i v8` reports one `v8 150.4.0` through `deno_v8 0.5.0`. The PathScale 0.6.5 graph was rejected because its transitive `nagoya 0.1.19` fails compilation on Windows with POSIX-only APIs.

## What the current executable verifies

- Creates one Deno `JsRuntime` (current-thread Tokio) with `deno_webidl 0.260.0`, `deno_web 0.291.0` (the release paired with `deno_core 0.413`) and the probe extension.
- `src/dom.js` installs a minimal DOM surface over the Blitz document and evaluates to a trusted-event dispatcher that Rust keeps. Afterwards `Deno` and `__bootstrap` are deleted from the global; `src/guest_test.js` checks that the guest cannot see them.
- DOM surface: `document.getElementById/createElement/createTextNode`, `Node.nodeType/parentNode/getRootNode/textContent/appendChild/removeChild`, `Element.localName/tagName/id/getAttribute/setAttribute`. Ops (`op_blitz_*`) borrow the shared Blitz document only for one synchronous call.
- Blitz owns the only tree. Wrapper identity: a JS-side `Map` from Blitz node id to wrapper (`===`, expandos survive mutation); handles live in a `WeakMap`, wrappers are not guest-constructible.
- DOM errors use deno_web's `DOMException`: `HierarchyRequestError` (self/ancestor/document insertion), `NotFoundError` (`removeChild` of a non-child), `InvalidCharacterError` (names). `appendChild` moves an attached node (Blitz's `append_children` alone does not detach it).
- Events: `Node` extends deno_web's `EventTarget`. Its spec dispatch builds the path from `parentNode`/`getRootNode` of objects with a `nodeType`, so capture/target/bubble follow the Blitz tree with no event code of ours. Rust resolves layout, hit-tests the centre of the JS-created `#button` with `BaseDocument::hit` (text hits retarget to the parent element) and calls the dispatcher; the guest verifies `isTrusted`, `target` and the order capture → target → bubble. A guest-dispatched event is untrusted.
- `AbortController`/`AbortSignal`: deno_web's own `03_abort_signal.js`, loaded after `02_event.js`/`02_timers.js` and exposed as globals (Pixi'VN `narration-hooks` constructs one at startup; the template failed with `ReferenceError: AbortController is not defined` on CI run 42526030667's artifact). `addEventListener(…, { signal })` on DOM nodes works through deno_web's `EventTarget`. Scoped regression checks in `src/dom_api_test.js` (not full spec coverage).
- Parses `fixtures/layout.html`, sets a 640×360 viewport and runs Blitz's style/layout resolve.
- Offscreen paint: `blitz_paint::paint_scene` into `anyrender_vello_cpu::VelloCpuImageRenderer` (Vello CPU raster, `anyrender_vello_cpu 0.8.1` for anyrender 0.6). The wgpu renderer (`anyrender_vello 0.6.0`) passed locally but crashed with `STATUS_ACCESS_VIOLATION` on the GPU-less Windows CI runners (stage markers showed every earlier phase passing); the CPU raster is deterministic and removes the wgpu stack (~50 crates) from the probe. Pixel checks: `#app` and the JS-created button backgrounds have their CSS colours, and both the `#app` text line and the button's inner area (inset past its UA border) contain painted text. `ROVES_PROBE_SCREENSHOT=<path>` also writes a PNG (the CI artifact). Text needs `blitz-dom`'s `system_fonts` feature: without it no font is loaded and nothing is drawn.
- Headless frame loop (`--exit-after-frames N`, default 8, paced at 60 Hz in real time): each frame runs `requestAnimationFrame` callbacks, performs a microtask checkpoint, polls the deno_core event loop once (deno_web timers) and resolves Blitz layout. `src/frame_test.js`/`src/frame_check.js` verify: one rAF chain step per frame with increasing timestamps; microtasks drained before the next frame; callbacks of one frame share a timestamp; a callback requested during a frame runs in a later one; a handle cancelled by an earlier callback is skipped; a throwing callback reaches a global `error` listener (deno_web `reportException`, global object made an `EventTarget`) without stopping the others; `setTimeout(…, 0)` fires. `element.style.x = v` / `setProperty` / `removeProperty` write Blitz inline declarations (reads are not implemented); the rAF-animated box reaches width 60 in layout and paint.
- Motion 12.38.0 (the visual-novel-template version), bundled from `js/` with esbuild: `animate(element, { x: [0, 100], opacity: [0.2, 1] }, { duration: 0.1 })` runs on its JS frameloop (no `element.animate` here, so no WAAPI path) over rAF and `performance.now`, finishes within the driven frames, and the paint shows the box translated by 100 px (Blitz layout ignores transforms; paint applies them) at full opacity. APIs it needed beyond the earlier surface: `window`, `performance` (deno_web, `setTimeOrigin` at bootstrap), `HTMLElement`/`SVGElement` classes (elements are now wrapped by namespace) and a `NodeList` interface for an `instanceof` test. A second animation (`opacity: 0.5`, no start value) reads its start through `getComputedStyle`; `src/motion_check.js` verifies the computed end value. `matchMedia` is still missing (Motion guards it). rAF timestamps come from `performance.now()`.
- `getComputedStyle(element)`: a live object; each read flushes styles only (`resolve_stylist`, no layout) and serializes Stylo's computed value (`stylo 0.8.0`, the version blitz-dom 0.2.1 uses, now a direct dependency for `PropertyId`). Longhands and custom properties work; shorthands, pseudo-elements and unstyled elements return `""`. Values are computed, not CSSOM resolved (`width: auto` stays `auto`).
- Wrapper/node lifecycle: wrappers of connected nodes are held strongly (expandos survive), wrappers of detached nodes only through a `WeakRef` (re-evaluated after each animation frame and on `appendChild`). A `FinalizationRegistry` callback tells Rust (`op_blitz_release`) when V8 collects a wrapper; Rust keeps a per-node wrapper count and frees a detached subtree with `remove_and_drop_node` once no node in it has a live wrapper. `textContent` and `removeChild` free replaced/removed subtrees immediately when nothing references them. Collections are forced from Rust with `Isolate::low_memory_notification` (no `--expose-gc`: that flag installs a non-deletable `gc` global the guest would see). `src/gc_test.js` creates 1000 unreferenced detached nodes plus a referenced detached node and a connected node with expandos; Rust forces collections, asserts the live Blitz node count returns to the starting level (±10) and `src/gc_check.js` checks the retained wrappers and expandos.
- Tree API: `childNodes`/`children` (static `NodeList` snapshots; live in browsers), first/last child, siblings, `insertBefore`, `contains`, `isConnected`, `append`/`remove`, `querySelector(All)` scoped to any node (Blitz/Stylo matching), `getElementsByTagName` on document and elements (live `HTMLCollection`, recomputed after tree mutations), `classList` (`DOMTokenList` over `class`), `className`, `has/removeAttribute`, `innerHTML` (html5ever provider; referenced replaced nodes survive detached) and `outerHTML`. HTML-namespace `<iframe>` nodes are wrapped as `HTMLIFrameElement`, a nominal interface with no browsing context (no `contentWindow`/`contentDocument`/`src` navigation), so React's `instanceof HTMLIFrameElement` active-element walk works under the single-document policy. HTML-namespace `<video>`/`<audio>` nodes are wrapped as `HTMLVideoElement`/`HTMLAudioElement` (globals, with `HTMLMediaElement`) whose only member is `canPlayType(type)`, returning `""` (cannot play) for every type: the probe has no HTML media playback backend and Deno provides none, so there is no `src`/`load`/`play` and no media events. It is the capability query PixiJS uses for video format detection. Test: `src/dom_api_test.js`.
- Namespaces: `document.createElementNS(namespace, qualifiedName)` (React/Pixi SVG; the template stopped with `s.createElementNS is not a function`). **Reuse:** the node is built by the pinned `blitz-dom 0.3.0-beta.4`'s own `DocumentMutator::create_element` with a `QualName` (`Namespace`/`Prefix`/`LocalName` re-exported by blitz-dom) through `op_blitz_create_element_ns`; no dependency, no second tree. Arguments use the deno_webidl helpers (two required, `DOMString` conversion so a Symbol throws `TypeError`, nullable namespace with null/undefined/"" as null). `dom.js` validates the qualified name as an XML QName (NCName approximated by ASCII letters/digits/`_.-` plus the BMP ranges of XML NameChar; astral characters rejected) with `InvalidCharacterError`, and throws `NamespaceError` for a prefix without namespace, `xml` outside the XML namespace and `xmlns` names/the XMLNS namespace used apart. No case folding, even for the HTML namespace; wrapper classes follow the namespace (HTML brands by exact local name, `SVGElement`, otherwise `Element`). `Element.prefix` and a qualified `tagName` come from `op_blitz_prefix`. Attribute names are ASCII-lowercased only on HTML-namespace elements; SVG and other namespaces keep their case in `get/set/has/removeAttribute` and mutation records (`viewBox`). Limits: no `setAttributeNS`/`getAttributeNS` (attributes live in the null namespace, e.g. `xlink:href` as a plain name), `setAttribute` keeps its ASCII name check. Test: `src/dom_api_test.js`.
- Scrolling (CSSOM View subset), needed by the visual-novel-template's router scroll restoration and narration centring (`narration-hooks-LJVJnQ7D.js`), which stopped with `ReferenceError: scrollTo is not defined`. **Reuse:** the pinned `blitz-dom 0.3.0-beta.4` already owns the scroll state (`BaseDocument::viewport_scroll`/`set_viewport_scroll`, per-node `scroll_offset`), which its own wheel scrolling writes and its painter reads (not re-verified against the crate source in this session); Taffy's `Layout::scroll_width`/`scroll_height` give the scroll extent (the same bound Blitz uses for wheel scrolling). Three narrow ops (`op_blitz_scroll_metrics`/`_component`/`_to` in `src/main.rs`) read and write that state; no dependency, no scroll engine of our own. Ops only touch Blitz state under the document borrow and never call into V8.
  - Supported: `window.scroll`/`scrollTo`/`scrollBy` and `Element.scroll`/`scrollTo`/`scrollBy` with `ScrollToOptions` (`left`/`top`/`behavior`, an omitted axis is kept) or `(x, y)`; one non-object argument and an invalid `behavior` throw `TypeError`; non-finite values become 0. `scrollX`/`scrollY`/`pageXOffset`/`pageYOffset`; `Element.scrollLeft`/`scrollTop` (read/write), `scrollWidth`/`scrollHeight`, `clientWidth`/`clientHeight`/`clientLeft`/`clientTop`; `document.scrollingElement`; `Node.parentElement`. The root element stands for the viewport (standards mode): its scroll offsets are the window's, its client size is the viewport, its scroll size is the document extent (root box plus Taffy overflow). Offsets are clamped to `0..scrollSize - clientSize` per axis. Elements scroll only on axes whose computed `overflow-x`/`overflow-y` is not `visible`/`clip` (`hidden` scrolls programmatically, as in browsers); other elements ignore writes and read 0. `getBoundingClientRect` subtracts the viewport scroll and the scroll offsets of ancestors but not the element's own (the probe reads Blitz's rect with the viewport and own offsets zeroed, so it does not depend on which offsets Blitz's rect already includes).
  - `scrollIntoView()`, `scrollIntoView(boolean)` and `{ block, inline, behavior }` (`start`/`center`/`end`/`nearest`, defaults `start`/`nearest`): aligns the border box in the client area of each scroll-container ancestor from inner to outer, then in the viewport, measuring again after each step. Detached elements and elements without a box do nothing.
  - Limits: `behavior: "smooth"` is validated and applied **immediately** (Blitz has no animated programmatic scrolling); no `scroll`/`scrollend` events are dispatched (the template's capture listener therefore never records element scroll positions); no scroll anchoring, `scroll-snap`, `scroll-padding`/`scroll-margin`, writing modes or RTL; Taffy's extent includes the right/bottom border term of its own formula; offsets are not re-clamped when content shrinks; wheel/keyboard scrolling in the window is still not forwarded (see `--window`). Test: `src/scroll_test.js` (viewport and a 2px-bordered `overflow: auto` box: offsets, dimensions, options and `(x, y)` overloads, clamping, smooth destination, rect movement, the template's centring formula, `scrollIntoView` alignments, cleanup); CI requires `"check":"scroll_viewport_and_elements","status":"passed"`.
- Geometry and input: `getBoundingClientRect`/`offset*` force style + layout (Blitz `get_client_bounding_rect`, scroll-corrected as above, and `offset_rect`); `innerWidth`/`innerHeight`; `matchMedia` with a small evaluator (media types, `not`, `and`, comma lists, width/height, orientation, prefers-reduced-motion/color-scheme, hover, pointer; not live); `focus()`/`blur()`/`activeElement` on Blitz focus with trusted focus/blur/focusin/focusout; `UIEvent`, `MouseEvent`, `PointerEvent`, `WheelEvent`, `KeyboardEvent`, `FocusEvent` over deno_web's `Event`. `ResizeObserver` (content/border/device-pixel boxes, `ResizeObserverEntry` with a `DOMRectReadOnly` `contentRect`) reads Blitz's Taffy layout and is processed after the rAF callbacks of each frame, with the spec's depth rule (the node itself counts, so a disconnected target has depth 1) and loop error. Targets not in the tree, never inserted or removed later, report 0x0 once, like browsers; test: `src/resize_observer_test.js`. Rust sends a trusted pointerdown/mousedown/pointerup/mouseup/click sequence at the hit-tested button and keydown/keyup to the focused element. Tests: `src/events_test.js`, `src/events_check.js`.
- `--window`: after the headless checks, the same document and runtime are presented in a real undecorated `blitz-shell` (winit 0.31 beta) window at logical (100,100), painted by the Vello CPU renderer through softbuffer. `src/window.rs` implements Blitz's `Document` trait: `poll` runs the JS frame step at 60 Hz (a ticker thread wakes the shell), `handle_ui_event` lets Blitz's `EventDriver` hit-test real OS input and forwards the resulting DOM events to the trusted JS dispatcher after the driver returns. The CI step screenshots the window and sends a real OS click (`SetCursorPos`/`mouse_event`) at the button the probe reports; `src/window_test.js` passes once a trusted pointer/mouse/click sequence lands inside the button. Scroll, wheel, text input, IME and touch are not forwarded yet.
- Storage and history: `localStorage`/`sessionStorage` come from `deno_webstorage 0.255.0` (paired with deno_core 0.413; localStorage in SQLite under `ROVES_PROBE_STORAGE_DIR`, default a temp directory). CI runs the probe twice on the same directory and requires `"local_storage_runs":2`, i.e. persistence across processes. `src/history.js` implements a single-document History/Location over deno_web's `URL`/`structuredClone`: push/replaceState (same-origin only, SecurityError otherwise), async back/forward/go with popstate and hashchange, fragment navigation; assign/replace/reload to another document are blocked and reported. Tests: `src/storage_test.js`, `src/history_test.js`, `src/history_check.js`. Compatibility with saves written by the current Servo-based Roves is not addressed.
- IndexedDB subset (`src/indexeddb.js`), persisted through the same deno_webstorage `localStorage`. Needed by the visual-novel-template's save system (`game_db` v2, store `saves` with `keyPath: "id"`, `autoIncrement` and indexes `id` unique, `date`, `name`, `gameVersion`; `put`/`get` in `readwrite` transactions), which stopped with `indexedDB` undefined after `AbortController` was fixed. **Reuse evaluation:** deno_core 0.413, deno_web 0.291 and deno_webstorage 0.255 ship no IndexedDB; Deno KV (`deno_kv`) is a privileged `Deno.openKv` API, not IndexedDB; `fake-indexeddb` is spec-complete but in-memory only (no supported durable backend, so saves would vanish on restart); `indexeddbshim` needs a WebSQL/sqlite3 backend we would have to write; `idb`/`idb-keyval`/`localforage` wrap a native IndexedDB. So the adapter is ours, kept to glue: values go through V8's structured serializer (`core.serialize`/`deserialize` with `forStorage`, the same clone semantics as `structuredClone`: `Date`, `Map`, `Set`, typed arrays survive), base64-encoded into one `localStorage` entry per record (`__roves_idb:1:<db>/<store>/<key>`) plus one JSON schema entry per database (`__roves_idb:1:<db>`: version, stores, key paths, key generators, indexes). No new dependency, no separate database file, no second runtime, no `Deno.*` exposure; scope is the existing origin storage directory. A database is read into memory on first open (every record is decoded once to compute its index keys); each `put`/`delete` writes its single `localStorage` entry when its request runs.
  - Supported (exactly the calls made by the template's `narration-hooks-LJVJnQ7D.js`): `indexedDB.open(name)` and `open(name, version)` with `onupgradeneeded` (`IDBVersionChangeEvent` with `oldVersion`/`newVersion`), `onsuccess`, `onerror`, `result` and `VersionError`; `db.objectStoreNames.contains()`, `db.createObjectStore(name, { keyPath, autoIncrement })` and `store.createIndex(name, keyPath, { unique })` during the upgrade, `store.indexNames`; `db.transaction(stores, "readonly"|"readwrite").objectStore(name)` with `oncomplete`, `db.close()`; store `put(value)` (in-line key, generated when the key property is missing or `undefined`; `ConstraintError` on a unique index), `get(key)`, `delete(key)`, `openCursor()` and `index(name).openCursor(null, "next"|"prev")`; cursor `key`, `primaryKey`, `value`, `continue()`, with the same request firing `success` again until `result` is `null`. Pagination is left to the consumer, as the template does it. Keys are numbers, strings and `Date`s; key paths are single property names. Values are cloned when `put` is called (later changes by the page are not stored); `get`/cursor values are fresh clones.
  - Ordering and events: requests of all transactions run in creation order, one deno_web timer task each, on the V8 thread (no native thread calls into V8); `put`/`get` complete asynchronously. A request created from a promise continuation of an earlier callback still joins the transaction; a transaction completes once a task passes with no request pending (later requests throw `TransactionInactiveError`). `success`/`error` events fire on the request only: no bubbling to the transaction or connection. Cursors read the store at each step, so writes made meanwhile are seen. Each step re-sorts the store, and if deno_web clamps nested timeouts as HTML does (4 ms after five levels, not verified) each step also costs a few milliseconds: acceptable for a save list, not for large datasets.
  - Not supported (absent or `NotSupportedError`): out-of-line keys (`put(value, key)`, stores without `keyPath`), key ranges and cursor queries, `IDBKeyRange`, `add`, `getAll`/`getAllKeys`/`count`/`clear`, index `get`, cursor `advance`/`update`/`delete`/`continue(key)`, `nextunique`/`prevunique`, `deleteObjectStore`/`deleteIndex`, `deleteDatabase`/`databases`/`cmp`, transaction `abort`/`commit`/`error`/`abort` events, `versionchange`/`blocked` between connections, array and binary keys, dotted or array key paths, `multiEntry`. An exception thrown inside `onupgradeneeded` does not abort the upgrade.
  - Storage limits, not hidden: transactions are neither atomic nor rolled back, because each `put`/`delete` is written to `localStorage` when its request runs (a crash leaves the requests already run). deno_webstorage enforces a 10 MiB quota per origin, shared with the game's own `localStorage`; a write over it fails that request with `QuotaExceededError`. Records are base64 of the V8 serialization (about 4/3 of the serialized size, which is close to JSON size for ASCII text and about twice for non-Latin-1 text). Whether the template's saves fit was not measured: a Pixi'VN save stores the exported game state including the narration history, which grows with play time, so many long saves could reach the quota; measure on the artifact before relying on it. Our `__roves_idb:` entries are visible through `localStorage.key()`/`length`, and a page calling `localStorage.clear()` deletes the saves (the current process keeps its in-memory copy until restart).
  - Test: `src/indexeddb_test.js`, driven by main.rs until done: template-shaped schema upgrade with indexes, generated keys, `get`/`delete`, overwrite by id, `Date`/`Map` values, store and index cursors in both directions with consumer-side pagination, reopen without a version, `index()` returning a cached `IDBIndex` linked to its store, and (from the second process) a string key containing `/` and `%` reloaded from storage (string keys escape `%`/`/` in the storage name). It reports `"indexed_db_runs"`: CI's `--window` run is a second process on the same storage directory and requires `"indexed_db_runs":2`.

- WebGPU teardown: before the headless fixture run and the `--game` run return (and drop the `JsRuntime`, hence deno_webgpu's wgpu Instance/Device/Queue), Rust awaits the bootstrap hook `shutdownGpu` with the event loop running: it settles a still-pending shared `requestDevice`; if the page has a shared device, the private op `op_blitz_gpu_wait_idle` (captured by `dom.js`, unreachable from the guest) blocks on wgpu-core's `Global::device_poll(device, PollType::Wait { submission_index: None, timeout: Some(120 s) })` through the `#[cppgc]` `deno_webgpu::device::GPUDevice`, and only after it succeeds does the hook call `device.destroy()`. The pinned deno_webgpu 0.227.0 has no `GPUQueue.onSubmittedWorkDone`, hence the native poll. Reason: wgpu-core 29.0.1's `impl Drop for Queue` (`src/device/queue.rs:208`) waits only about 6 s in fixed steps for the last successful submission and then panics with "We timed out while waiting on the last successful submission to complete!"; CI run 42679143051 hit it after the unmodified visual-novel-template had reached its menu (`game_page` pathname `/`, `navigator.onLine` true, Start/Continue/Load/Settings, 0 errors), on the GPU-less Windows runner (the adapter there is presumably a software one such as WARP; not confirmed from the log). The exact Queue Drop budget was not re-read from the crate sources; the CI evidence line is what confirms the fix.
- `--game <dist dir>`: loads a real game build instead of the fixture (`src/game.rs`). Blitz parses its `index.html` with the content root `game://content/` as document and base URL (like the Servo shell's boot URL, so a client-side router matches its `/` route instead of rendering "Not Found"; module, stylesheet and fetch URLs resolve to the same files as before) and a `NetProvider` serving `game://content/...` from the directory (stylesheets, fonts); deno_core runs the page's `<script type="module">` through a matching `ModuleLoader` (`..` and other hosts refused; JSON only with `with { type: "json" }`). Errors and unhandled rejections are collected (rejections now become `unhandledrejection` events instead of terminating the runtime; `console` comes from deno_web). The run prints a report (document URL/pathname, `navigator.onLine`, whether the page shows a router "Not Found" or "No internet connection" text, the first button labels with a start-menu heuristic, load errors, script errors, nodes under `#root`, page text) and an optional screenshot; CI re-emits the route/connectivity fields as a separate annotation. `navigator.onLine` is `true`, as in the Servo shell: a browser-style hint that the device is not known to be offline, not a guarantee that a remote request succeeds. CI runs it on visual-novel-template's unmodified build, with the default fetch policy and no extra flags, as a smoke test (it fails on a panic or a missing page report) whose report lists the missing Web APIs and any refused fetch.
- `fetch` on `deno_fetch 0.284.0`: `Headers`, `Request`, `Response`, `FormData` and the `data:`/`blob:` fetches are Deno's. `src/fetch.js` only adds the game policy around Deno's (unexposed) `fetch`: `game://content/...` reads the game's files through `op_blitz_game_read` and answers with a Deno `Response` (404 when missing or outside `--game`). Remote requests go to any *safe* origin by default, with no allow-list or flag (`src/net_policy.rs`): `https:` only; no URL credentials; IP literals must be public (loopback, private, link-local, CGNAT, documentation, multicast, reserved, unique-local and IPv4-mapped/NAT64/6to4 forms of those are refused, checked from JS before every hop and again in deno_fetch's `request_builder_hook`); host names go through a custom deno_fetch DNS resolver that refuses the whole answer if any resolved address is non-public, and hyper connects only to the addresses it returns, so DNS rebinding to a private address is refused on every new connection; the document's `Content-Security-Policy` from `<meta http-equiv>` in `<head>` (as parsed at load) is enforced as `connect-src` with the `content-security-policy` 0.8.1 crate production Roves uses. On top, a CORS request without preflight: GET/HEAD, safelisted request headers only (`Accept`, `Accept-Language`, `Content-Language`), no credentials (`credentials: "include"`, URL userinfo and modes other than `cors` reject), `Origin` set to the document's origin (`null` for `game://` and after a cross-origin redirect), `Access-Control-Allow-Origin` `*` or that origin on every response including redirects, redirects followed by hand (`redirect: "manual"` underneath, at most 20, every hop revalidated by the same Rust policy and CSP; `redirect: "error"` honoured, `"manual"` rejected), response headers filtered to the safelisted ones plus `Access-Control-Expose-Headers` (never `Set-Cookie`); `http:` (outside the fixture), `file:` and every other scheme reject with TypeError, and refusals are logged as `ROVES_PROBE_FETCH_BLOCKED`. https uses Mozilla's roots (`deno_tls`). The only exception is fixture mode (no `--game`): its own plain-http loopback test server, registered from Rust, never in a game run. Not reachable from the game: Deno's raw `fetch`, `Deno.createHttpClient`, client certificates. Worker scripts still come only from blob:/data:/`game://`. Limits: no preflight (so no remote POST or custom headers), no cookies; CSP `<meta>` elements added by scripts after load are not applied, and CSP is not applied to `game://`, `data:` or `blob:` fetches; no proxies: deno_fetch's `create_http_client` always applies the environment proxies (`Options.proxy: None` does not disable them), and through a proxy the public-address check would only see the proxy, so while any variable deno_fetch's `proxy::from_env` reads is set and non-empty (`ALL_PROXY`/`all_proxy`, `HTTPS_PROXY`/`https_proxy`, and `HTTP_PROXY`/`http_proxy` unless `REQUEST_METHOD` is set) every request is refused, fixture loopback included (fail closed; `NO_PROXY` is not trusted; the fixture run stops with a message asking to unset it); `new Request("relative")` resolves against the initial document URL while `fetch("relative")` follows `pushState`; no `EventSource`. Tests: `src/fetch_test.js` (loopback fixture server, refused destinations and CSP; no network needed: `https://localhost:8443` (a Fetch-allowed port; bad ports such as 1 are rejected before DNS) is refused by the resolver, and main.rs asserts the resolver did it), the Rust address/URL table in `net_policy::self_check`, `src/fetch_check.js`.
- Images: `createImageBitmap`/`ImageBitmap` from `deno_image 0.36.0` (PNG/JPEG). deno_webgpu 0.227 lacks `GPUQueue.copyExternalImageToTexture`, which PixiJS uses for every image texture; `dom.js` polyfills it over `writeTexture` (ImageBitmap pixels via `op_blitz_image_bitmap_rgba`, ImageData; origin, flipY, premultipliedAlpha, bgra). Tests: a 2×2 PNG decoded headless (`fetch_test.js`) and, in the GPU scenario, a Pixi sprite loaded with `Assets.load` from a PNG data URL whose pixel is read back.
- Dedicated `Worker` (`src/worker.js`, `src/worker_scope.js`, `src/worker.rs`): PixiJS's `WorkerManager.isImageBitmapSupported` starts a blob-URL worker before every texture load. No deno_core 0.413-paired extension provides `Worker` (Deno's is part of `deno_runtime`, with permissions and `Deno.*`). Each worker is a real separate `JsRuntime`/V8 isolate on its own thread with only deno_webidl/deno_web: `DedicatedWorkerGlobalScope` (`self`, `name`, `postMessage`, `close`, `onmessage`/`onmessageerror`/`onerror`), events, timers, `console`, `structuredClone`, `URL`, `Blob`, text encoding, base64, `performance`. Not in the worker: DOM, `fetch`, `createImageBitmap`, `importScripts`, WebGPU, storage, `navigator`, `Deno`. Pixi's check therefore truthfully answers `false` and Pixi decodes images on the main thread with deno_image. Owner side: classic scripts from blob: (deno_web blob store; `URL.createObjectURL` from deno_web), data: or `game://content/` URLs with a JavaScript MIME type (otherwise an `error` Event), messages in order via V8 structured serialization delivered by the frame loop's event loop poll, `terminate()` stops the isolate even mid-script. Limits: no module workers (`TypeError`), no transfer lists (`DataCloneError`), no nested/shared workers, an uncaught error not cancelled in the worker ends it (as in Deno) and fires a cancelable `ErrorEvent` at the Worker, then at the page if not cancelled. Test: `src/worker_test.js` (stage `worker`, CI check `dedicated_worker_pixi_image_bitmap_probe`), including Pixi 8.19.0's check worker verbatim.
- Web Audio (`src/audio.rs`, `src/web_audio.js`): no Deno extension implements it, so the API sits on `web-audio-api 1.7.0` (Rust, maintained, already in the lock) with a headless `"none"` sink that renders in real time without a device (the crate's cpal backend is off; real output is still to do). Exposed: `AudioContext` (state machine with `statechange`, `resume`/`suspend`/`close`, `currentTime`, `sampleRate`, latencies), `AudioParam` (value and all automation methods), `AudioListener`, `AudioDestinationNode`, `GainNode`, `ConstantSourceNode`, `OscillatorNode`, `ChannelMergerNode`, `ChannelSplitterNode`, `StereoPannerNode` (native, so standardized-audio-context does not fall back to its merger/wave-shaper/buffer faker; offline render checks `web_audio_channel_routing_offline` and `web_audio_stereo_panner_offline`), `connect`/`disconnect` overloads to nodes and params. Native objects are cppgc handles. The crate runs `ended` callbacks on its own event thread: they only push the node id into a Rust queue; the frame loop drains it and re-reads context state on the V8 thread (`dispatchPendingEvents`), so no V8 call happens off that thread. The crate signals spec errors with panics (`IndexSizeError - …`); ops catch them and JS rethrows the named `DOMException`/`RangeError`, after validating arguments itself. Not exposed (absent, not faked): buffers/`decodeAudioData`, the other node types, `OfflineAudioContext`, `PeriodicWave`, `ScriptProcessorNode`, `AudioWorklet`. Without `ScriptProcessorNode`/`AudioWorkletNode`, standardized-audio-context's disconnect self-test fails and it wraps every node's `disconnect` with its own connection bookkeeping (functional, slightly more work per disconnect). Tests in `dom_api_test.js` and `fetch_test.js`.

Negative checks performed on 2026-11-07: disabling the wrapper cache fails with `same node must return the same wrapper`; dispatching the click with `bubbles: false` fails with `click listeners did not run in DOM order`; iterating the live rAF map instead of a snapshot fails with `rAF timestamps must increase`; skipping the microtask checkpoint and event-loop poll fails with `microtasks must drain before the next frame`; driving no frames after starting Motion fails with `Motion animation did not finish`; building without `system_fonts` fails with `the button text must be painted over its background`. The offscreen screenshot was inspected visually on the local Windows machine (text and boxes as expected); that is an offscreen render, not a window presented on screen.

`anyrender::render_to_buffer` with the GPU `VelloImageRenderer` panics in `anyrender_vello 0.6.0` (zero-length buffer); fixed in 0.15.0. The CPU renderer used now resizes correctly.

Cost of deno_web here: 15 more crates in the probe lockfile, including a second `cssparser` (0.36.0, Stylo uses 0.35.0) and `brotli`. Not measured: binary size, startup, memory.

### Option A chosen over a JS DOM library

The technical handoff left open a JS DOM library mirrored into Blitz (option B). Checked on 2026-11-07: `happy-dom 21.0.4` imports Node built-ins (`vm`, `fs`, `buffer`, `stream`, `url`), unusable in this runtime without exposing a Node layer. `linkedom 0.18.15` is pure JS, but its `dispatchEvent` is "intentionally simplified" (no real capture phase, which React's root listeners rely on) and its `MutationObserver` uses non-standard record matching, so mirroring into Blitz would need hooks into its internals, plus a second tree in memory. The probe therefore keeps Blitz as the single tree and reuses deno_web for Event/EventTarget/DOMException.

### Blitz 0.2.1 gaps found (fixed in 0.3.0-beta.4, which the probe now uses)

- `DocumentMutator::set_style_property` sets no restyle hint (`set_attribute` does), so inline style writes may never be restyled. On 0.2.1 the probe set `RestyleHint::RESTYLE_STYLE_ATTRIBUTE` itself; 0.3.0-beta.4 does it inside Blitz, so the workaround is gone. Negative check: without the hint, `computed style must be live and flush pending writes` fails.
- `blitz-paint` draws an element's own background and border before its opacity layer, so `opacity` only fades children and text. On 0.2.1 this was reported as a known gap; on 0.3 the probe asserts the faded pixel. 0.3.0-beta.4 draws the background inside the layer.
- `anyrender_vello 0.6.0` `render_to_vec` (see above; the probe no longer uses the GPU renderer).

These argue for moving the probe to the Blitz 0.3 line once its betas are usable here; that changes Stylo/anyrender versions and needs its own check.

### Identity constraint found

Update for Blitz 0.3: `NodeId` is versioned (slot index + generation), so a handle held by a wrapper resolves to `None` once its node is freed instead of aliasing a new node. The probe passes handles to JS as numbers and still detaches instead of freeing; the remaining work is to free nodes when wrappers are collected.

Original 0.2 finding:

Blitz stores nodes in a slab and **reuses the ids of dropped nodes**. A wrapper cache keyed by node id is therefore only sound while no referenced node is dropped. The probe's setter uses `DocumentMutator::remove_node` (detach) instead of `remove_and_drop_*`, so detached nodes stay allocated, and the cache is strong. That leaks detached nodes; production needs a GC-aware lifecycle (e.g. dropping a Blitz node only after its wrapper is collected, possibly via deno_core cppgc objects) before nodes can be freed.

The probe does not open a browser window, inspect pixels or measure frame pacing/CPU/GPU. It proves runtime-to-document reads/writes and wrapper identity only.
